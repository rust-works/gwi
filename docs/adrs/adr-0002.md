# ADR-0002: MCP Tools Restrict the Local Paths Callers Choose

## Status

🟡 Proposed (2026-10-09, [#45](https://github.com/rust-works/gwi/issues/45))

## Context

Two `gwi-mcp` parameters take a local path chosen by the caller, who is an assistant that a
prompt injection can steer:

- the `text_path` and `values_path` sources of the Drive write tools, read as UTF-8 and written
  into a Google Doc or Sheet;
- `output_file` on the Gmail and Drive read tools, which writes the rendered result to disk.

omni-dev, which these tools are ported from, accepts any readable regular file and writes to
any path the server user can write. The Drive write gate checks the *target* file, not where the
content came from, so `drive_docs_append` with `text_path: "~/.ssh/id_rsa"` sends a private key
to Google, and `output_file` can overwrite a shell profile. The Gmail-only server had no
read-a-file-and-upload channel; the Drive write tools added one. ADR-0001 lets gwi change
behaviour omni-dev keeps.

## Decision

We will check every such path against an operator policy before the file is read or written.

1. **Resolve, then test.** The path is canonicalised (symlinks followed, `..` collapsed; for a
   new file, its parent) and the resolved path is tested by component, not by string prefix. The
   I/O uses the resolved path.
2. **Allowed directories.** `mcp.allowed_paths` in `settings.json` lists them. When unset the
   default is the server's working directory and the system temp directory; when set it replaces
   the default, and an empty list allows nothing.
3. **Credential locations always lose.** A fixed list (`~/.gwi`, `~/.omni-dev`, `~/.ssh`,
   `~/.gnupg`, `~/.aws`, `~/.kube`, `~/.docker`, `~/.netrc`, `~/.config/gcloud`,
   `~/Library/Keychains`, gwi's state directory) is refused even when `allowed_paths` covers it.
4. **Operator-only.** The policy is not a tool parameter, like the lease policy parameters.
   The CLI is not restricted: its paths are chosen by the person at the terminal.
5. **Fail closed.** Settings that cannot form a policy (a relative `allowed_paths` entry) refuse
   every path, with the reason, and leave the tools that take no path working.
6. `O_NONBLOCK`, used only so opening a FIFO cannot block, is cleared once the file is known to
   be regular.

## Consequences

- A prompt-injected assistant can no longer exfiltrate a credential file through a write tool
  or overwrite one through a read tool, and a symlink or `..` cannot get around the check.
- A caller that passes a path outside the working and temp directories now gets a clear error
  and the operator has to list the directory. This is a deliberate difference from omni-dev.
- The default is broad when the client starts the server in `$HOME`: the deny list still
  protects credentials, other secrets in the home directory are readable. An operator who
  cares sets `allowed_paths`.
- The deny list is fixed, not extensible, and the check is not atomic with the open: someone who
  can already write inside an allowed directory can race a swap. Both are accepted for now.
