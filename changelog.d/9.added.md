- Per-PR changelog fragments. A PR adds `changelog.d/<id>.<type>.md` instead of editing
  `CHANGELOG.md`, so two PRs no longer conflict on the changelog. `scripts/changelog.py`
  validates the fragments (`check`), requires a PR to carry one unless waived with the
  `no-changelog` label or a `[no changelog]` line (`check-pr`), and assembles a release
  section (`collect`). A `Changelog fragments` workflow runs it on pull requests and the
  merge queue (#9).
